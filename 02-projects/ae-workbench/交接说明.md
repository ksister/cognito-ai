## 1 代码地图

工作台代码在 `workbench/`（Next.js 16 App Router + TypeScript，`dev` 端口 4321）。

数据流（一条记录的完整旅程）：

```text
截图/粘贴 → 记一笔(app/new + components/record-form.tsx)
  → api/extract（VL/AI 出草稿）
  → 黄区人工核对（D3 硬门槛）
  → api/records POST 保存
      ├─ lib/kb.ts createRecord → KB_DIR/customers/<客户>/records/*.md（本地唯一事实源，D1）
      ├─ lib/kb.ts saveScreenshotBatch → files/ 截图按规则命名落盘
      └─ lib/lark-bitable.ts pushRecordToFeishu → 飞书建行/更新（cli --as user，D5）
          └─ 兜底 lib/feishu.ts 生成 TSV 供「复制为飞书行」（D12）
```

关键文件职责：

| 文件 | 职责 |
|---|---|
| `lib/kb.ts` | 本地 markdown 读写（记录/客户档案/需求/截图）、local_id 分配、私有 schema 缓存 |
| `lib/feishu-schema.ts` | 飞书表结构配置解析校验、`buildCreateFields` 字段映射、AI 提取的选项约束（D8/D13/D14）、版本号归一化 |
| `lib/feishu-schema-load.ts` | 读/写私有 `KB_DIR/config/feishu-table.json`（真实列名/选项/fieldId 只在此） |
| `lib/lark-bitable.ts` | lark-cli 建行/更新/传附件、错误归因（登录过期/未配置/未命中）、api 模式兜底 |
| `lib/feishu.ts` | 剪贴板 TSV/CSV 导出（schema 驱动） |
| `lib/vl.ts` / `lib/ai.ts` | 截图通义 VL / 文字 AI 提取 |
| `api/records` | 保存（本地落盘→推飞书→回写）、列出、更新+同步 |
| `components/record-form.tsx` | 记一笔表单 + 黄区核对 |
| `components/record-actions.tsx` | 记录操作（同步飞书 / 复制行 / 状态） |

配置来源（D9/D11/D13）：仓库只放 `workbench/config/feishu-table.example.json`（虚构示例）与 `.env.example`（占位符）；真实配置在私有 `KB_DIR/config/feishu-table.json` 与 `.env.local`（gitignore）。

## 2 进行中的分支状态

- **`cursor/t15-paste-dedupe`（T15，待评审，PR 目标 `feat/screenshot-first-mvp`）**：粘贴一次出现两张图。
  - 原因（代码 + 真机都可证）：一次粘贴的 payload 里同一张图会在两个地方各列一份——`clipboardData.items`（kind=file）和 `clipboardData.files`；剪贴板图片的 `File` 是浏览器现造的（名字固定 `image.png`、`lastModified` 取创建时刻），两次拿到的不是同一个对象，旧的 `名称-大小-lastModified-类型` 去重键对不上，两张都进了截图列表。
  - 改法：新增 `lib/shot-intake.ts`。图片先统一压缩成 JPEG，再对字节求指纹（安全上下文 SHA-256，局域网 http 等非安全上下文用两个 32 位哈希兜底）；指纹相同即同一张，与文件名/大小/时间无关。`known`（已加入）和 `pending`（正在压缩哈希）两个集合一起判重，挡住两个粘贴监听同时处理同一个事件；粘贴/拖入在 `record-form.tsx` 里串行排队处理，删掉某张截图会放掉它的指纹，允许再粘一次。
  - 验证：`shot-intake.test.ts` 10 条单测（含连粘 20 次、并发两次、删后可重粘、无 crypto.subtle 兜底）；无头 Chrome 打 4321 的 `/new`，合成剪贴板事件（同一张图两个 File 对象）：**改前**一次粘贴出 2 张、连粘 20 次顶到 9 张上限；**改后**一次粘贴 1 张、连粘 20 次仍是 1 张，换一张内容不同的图正常变成 2 张。

## 3 已知的坑

1. **Next.js 16 破坏性变更**：以 `node_modules/next/dist/docs/` 为准，勿套旧版 Next 的 API（见 `workbench/AGENTS.md`）。
2. **lark-cli user 登录过期**（T10）：access token 约 2 小时过期；带 `--scope offline_access` 登录后 refresh token 有效 7 天、lark-cli 会自动刷新。登录时务必带 `--domain base,drive --scope offline_access`（见 .env.example）。代码仍有过期兜底（`cli_auth_expired` + 重登命令 + 复制兜底）。
3. **多选/人员字段**：cli 写多选用字符串数组；人员字段必须 `open_id`（ou_…），写显示名会 not_found（PR #6 实测结论）。
4. **飞书字段 ID**：`LARK_FIELDS` 写死在代码里（D11 允许）；真实 fieldId 以私有 `feishu-table.json` 为准。
5. **本地先落盘、飞书失败不回滚**（D4）；「我的思考」「原始聊天记录」归用户、AI 不得改写（D6）。
6. ~~端口不一致~~ 已统一为 4321（T7）；README 里泄露的真实本机路径也已改为占位。
7. **PR 目标分支必须重看**（技术方向说明第 0 节）：叠加 PR（基分支是另一个 PR 的分支）在上层 PR 合并后，要先把目标分支改回 `feat/screenshot-first-mvp` 再合；合并后必须用 `git show feat/screenshot-first-mvp:<文件>` 确认改动确实到了主工作分支。T5/T7 曾因基分支是 T4 分支而误留在 T4 分支（#13/#14），后以 #17/#18 补救。
8. **lark-cli 单选选项**（T13）：`+field-list` / `+field-get` / 原始 v3 API 都只返回每个选项的 `{hue, lightness, name}`，**不返回选项 id**；`+field-update` 是**整体覆盖**（完整 PUT），没有「只追加一个选项」的接口。改单选选项时，必须**先读出飞书当前的完整选项再追加**；读不到（字段为空或格式变化）就停止报错，**绝不能用本地配置覆盖飞书**（D16）。
9. **飞书按名称保留已有选项**（11-09 在测试表实测）：增删一个选项**不会**影响其他选项的颜色，也**不会**影响已有记录的客户列值。所以 v3 下「原样保留 `{hue, lightness, name}` 再追加新选项」是安全做法；实测中 42→43→42 全程原有选项颜色与 3 条记录值均不变。
10. **同一记录的飞书写入必须排队**（T11 评审 1）：保存秒回后后台写入还没写回 `feishu_record_id`，此时再保存或同步就没有行号，会建第二行。所有把记录推给飞书的入口都走 `queueSavedRecordPush`，不要直接调 `pushSavedRecord`（它不做排队）。另外 `local_id` 只在各自 KB 内唯一：换一个 KB_DIR（或同事）同一天会撞号，D18 的人员缩写就是为此。
11. **看配置、看接口返回时只输出字段名、数量和布尔值，不输出值**（11-10 教训，用户明确要求）：实现 AI 的会话内容会发到模型服务商的服务器，所以「只在自己电脑上打印、没发给别人」不等于没外传。之前为了确认 `config/feishu-table.json` 的结构和 `/api/feishu/meta` 的返回，把里面的**取值**（Base token、客户选项名）打进了会话。以后判断「配好了没有 / 有没有 fieldId / 选项有几个」，只输出：字段名、条数、true/false、以及「有值/为空」。
12. **`/api/feishu/meta` 曾把 `baseToken`、`tableId` 一起返回给浏览器**（11-10 已删，见 PR：前端从未用到这两个字段）。以后往这个接口加字段前先问：浏览器真的需要吗。`cliPath`（本机路径）目前仍会返回，属同类问题，未改。
13. **一次粘贴里同一张图会出现两次**（T15 已修，别再退回按文件名去重）：`clipboardData.items` 和 `clipboardData.files` 各列一份，剪贴板图片的 `File` 是浏览器现造的（名字固定、`lastModified` 每次都不一样），按元数据去重挡不住。判重一律走 `lib/shot-intake.ts` 的内容指纹；以后新加粘贴/拖放入口也要走 `record-form.tsx` 的 `addFiles`，别绕过去直接 `setShots`，否则又会出重复。
