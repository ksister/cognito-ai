# 工作台桌面版方案（Electron 便携版 A）

> 评审结论：**选 A（Electron 便携版）**，B（Tauri + Node）不做。先完成 T11，再做本方案的最小可运行原型。

## 1. 结论与本轮修正

- **选 A**：Electron 便携版，单 exe、免安装、双击即用。
- **不另外打包 node.exe**：Next standalone 服务直接跑在 Electron 自带的 Node 上（`utilityProcess.fork` 或 `ELECTRON_RUN_AS_NODE`）。
- **sharp 要实测**：它是 Node-API 模块，正常应能直接在 Electron 的 Node 里用，但必须实测确认。
- **lark-cli 要实测**：同样要验证能否用 Electron 自带的 Node 运行。
- **体积先实测，不靠估算**：先做最小可运行便携版，报告真实 exe 大小和首次/后续启动耗时；超过 200MB 再评估 B。

## 2. 现状与约束

| 项 | 现状 |
|---|---|
| 前端/后端 | Next.js 16（App Router），API 路由在 `workbench/src/app/api/*` |
| 图片处理 | `sharp`（Node-API 原生模块） |
| 飞书 | 本机 `lark-cli.exe`（Node 包），`--as user` 凭证在 lark-cli 自己的 keychain |
| 数据 | `KB_DIR`（纯数据目录）里的 `customers/`、`config/` |
| 配置 | `workbench/.env.local`（KB_DIR、LARK_*、AI_*、DASHSCOPE_*） |
| 已定 | T17 方案 A：工作台内显示飞书登录状态 + 「登录飞书」按钮；不做开机自启 |

## 3. 运行方式

1. `next build` 用 `output: "standalone"`。
2. Electron 主进程用 `ELECTRON_RUN_AS_NODE`（或 `utilityProcess.fork`）跑 `standalone/server.js`，端口用 0 让系统分配。
3. 窗口加载 `http://127.0.0.1:<实际端口>`。
4. **不打包独立 node.exe**，复用 Electron 自带的 Node。

## 4. 最小可运行原型（第一步，用于实测体积与启动）

只做四件事，验证可行性：
1. 能打开窗口、加载首页。
2. 调用一次 `sharp` 压缩（用一张真实截图）。
3. 执行一次 `lark-cli --version`（用 Electron 的 Node 启动）。
4. 报告：真实 exe 大小、首次启动耗时、后续启动耗时。

控制体积的手段：
- standalone 只保留实际用到的依赖，去掉 dev 依赖。
- 用 asar 打包。
- 便携版压缩。
- 实测超过 200MB 再回来评估 B。

## 5. lark-cli 与登录

- lark-cli 作为 `extraResources` 打包，`LARK_CLI_PATH` 指向 `process.resourcesPath` 下的路径。
- 登录信息**不进安装目录**：lark-cli 自己把 token 写用户级 keychain/配置。
- T17 的「登录飞书」按钮：`POST /api/feishu/login` 起 `lark-cli auth login --domain base,drive --scope offline_access`，用 `shell.openExternal` 打开授权页；状态从 `lark-cli auth status` 读。

## 6. 数据（KB_DIR 与 .env.local）

- 放用户数据目录：`%APPDATA%\<产品名>\`
  - `kb/` = `KB_DIR`
  - `config/feishu-table.json` = 私有表结构
  - `.env.local` = 模型 key 等
- 由 T20 首次设置向导写入；安装目录只放程序，升级覆盖不影响数据。

## 7. 关闭窗口与后台写入

- 主进程维护「后台写入中」计数（由 `api/records` 的后台写入上报）。
- 关闭窗口时若有未完成写入：**缩到托盘** + 提示「正在写入飞书，完成后自动退出」；计数归零后再退出。
- 托盘菜单：显示工作台 / 退出。

## 8. GitHub Actions 打包与发布

- `windows-latest`：`npm ci` → `next build` → electron-builder → 产出便携 exe / setup.exe。
- 发布到 GitHub Release（tag 触发）。
- **安装包不得包含**：任何 key、客户数据、私有 `feishu-table.json`、`.env.local`。

## 9. 体积与签名（待实测）

- 目标：≤200MB；超过则重新评估 B。
- 无代码签名时，Windows SmartScreen 会提示「未知发布者」，需点「更多信息 → 仍要运行」。

## 10. 落地顺序

1. 完成 T11（拆并行请求 + 前端三件事 + PR）。
2. 做最小可运行便携版，实测体积与启动。
3. T20 首次设置向导。
4. Electron 外壳完善（托盘、登录状态、关闭等待）。
5. GitHub Actions 打包 + Release。
